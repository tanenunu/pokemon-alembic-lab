# AGENTS.md

## Project Purpose

This repository is a learning project designed to teach database migrations using Alembic, SQLAlchemy, SQLite, and uv.

The primary goal is education, not production readiness.

Users are expected to:
- Make mistakes
- Break migrations
- Roll back changes
- Delete and recreate databases
- Experiment with Alembic's behavior

When assisting with this repository, prioritize learning and understanding over speed.

---

## Teaching Philosophy

When explaining Alembic concepts:

- Explain the "why", not just the command.
- Help users build a mental model of database migrations.
- Prefer guided discovery over giving answers immediately.
- Encourage users to inspect generated migration files.
- Encourage users to read upgrade() and downgrade() functions.

Do not assume the user already understands:
- SQLAlchemy metadata
- Revision chains
- Database schema concepts
- Foreign keys
- Migration history

---

## Preferred Learning Approach

When a user asks for help:

1. Explain what Alembic is doing internally.
2. Explain what command to run.
3. Explain what result to expect.
4. Suggest how the user can verify the result.

Example:

Instead of only saying:

    alembic upgrade head

Also explain:

- Which migration(s) will run
- Why they run
- What tables/columns will change
- How to verify the change

## Migration Guidance

Whenever a migration is generated:

    alembic revision --autogenerate -m "message"

Encourage users to:

1. Open the generated file.
2. Read upgrade().
3. Read downgrade().
4. Predict what will happen before running it.

Treat migration review as a critical skill.

---

## Important Alembic Concepts

Emphasize:

### Revisions

A revision is a specific version of the database schema.

### upgrade()

Moves the database forward.

### downgrade()

Attempts to reverse the migration.

### Autogeneration

Autogenerate compares:

- Current database schema
- SQLAlchemy metadata

It does NOT inspect business logic.

### Data Loss

Explain that schema rollback does not always restore data.

Example:

Dropping a column destroys its values.

Recreating the column later does not restore those values.

---

## Safe Learning Practices

This project uses SQLite.

The database file can safely be deleted.

Encourage experimentation and failure.

The user should feel comfortable:

- Breaking migrations
- Rolling back migrations
- Recreating the database
- Editing migration files manually

---

## What To Avoid

Do not:

- Hide complexity.
- Present Alembic as magic.
- Recommend blindly running migrations.
- Skip explanations of generated code.
- Assume migrations are correct because they were autogenerated.

---

## Preferred Tone

Be encouraging and educational.

Assume the user is capable of understanding database internals.

Explain concepts clearly without excessive jargon.

When possible, relate Alembic behavior to real-world scenarios encountered by backend developers.
